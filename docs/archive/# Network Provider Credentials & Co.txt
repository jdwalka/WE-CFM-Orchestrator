# Network Provider Credentials & Configuration To-Do List

This document outlines the network configurations, endpoints, and credentials required to resolve rate limits, CORS errors, and network connectivity issues within the WE-CRYPTO Orchestrator. 

**Priority #1:** Coinbase

---

## 1. Coinbase (Primary Priority)

Currently, the orchestrator connects to Coinbase entirely via **Public Unauthenticated Endpoints**. If you are encountering network errors (e.g., `429 Too Many Requests`, `403 Forbidden`, or websocket disconnects), upgrading your connection methods and adding credentials will dramatically improve stability.

### A. WebSocket Connection (WSS)
* **Current Usage:** `wss://advanced-trade-ws.coinbase.com` (Subscribing to `ticker` and `candles` channels).
* **Issue:** Public websockets are heavily rate-limited and deprioritized by Coinbase during high market volatility.
* **To-Do:**
  - [ ] **Generate Advanced Trade API Key:** Go to Coinbase Developer Platform (CDP) and generate an **API Key & Secret**.
  - [ ] **Implement JWT Auth for WSS:** Coinbase Advanced Trade websockets require a JSON Web Token (JWT) signed with your API Secret to authenticate the connection.
  - [ ] **Update `candle-ws.js`:** Modify the connection logic to pass the JWT in the initial connection or subscribe payload. This unlocks dedicated bandwidth and higher rate limits.

### B. REST Endpoints (HTTPS)
* **Current Usage:** 
  - `https://api.exchange.coinbase.com/products/{id}/stats`
  - `https://api.coinbase.com/v2/prices`
* **Issue:** Public REST endpoints are severely rate-limited (often 3-10 requests per second across the entire IP).
* **To-Do:**
  - [ ] **Migrate to Authenticated REST:** Use your CDP API Key/Secret to sign REST requests (via HTTP headers `CB-ACCESS-KEY`, `CB-ACCESS-SIGN`, `CB-ACCESS-TIMESTAMP`).
  - [ ] **Bypass Cloudflare:** Authenticated requests are routed through dedicated API gateways, drastically reducing Cloudflare `520` or `403` blocks.

### C. gRPC / FIX APIs (Optional Enterprise)
* **To-Do:**
  - [ ] If latency remains an issue, investigate if your Coinbase institutional account qualifies for **FIX Protocol** (Financial Information eXchange) or **gRPC** streams, which offer sub-millisecond latency compared to standard WSS.

## 2. Binance & Bybit (Secondary Priority)

### Binance
* **Current Usage:** `https://api.binance.com/api/v3` (HTTP) & `wss://stream.binance.com:9443` (WSS)
* **To-Do:**
  - [ ] **Add API Keys:** Binance drastically increases your request weight limits (from 1200/min to 6000/min) if you include a valid `X-MBX-APIKEY` header, even for public data.
  - [ ] **Network Config (Proxy):** Binance aggressively geoblocks US IPs. Ensure your `tauri-bridge.js` proxy has specific routing rules to forward Binance requests through non-US VPN nodes or proxies.

### Bybit
* **Current Usage:** `https://api.bybit.com/v5`
* **To-Do:**
  - [ ] **WSS Migration:** Currently, Bybit is queried heavily via HTTP for Funding Rates and Recent Trades. Migrate these to Bybit's `wss://stream.bybit.com/v5/public/linear` to reduce HTTP overhead and avoid TCP handshake latency.

---

## 3. Blockchain RPCs (Solana, Ethereum)

### Solana (Base Layer)
* **Current Usage:** `https://api.mainnet-beta.solana.com` (Public RPC)
* **Issue:** The public Solana RPC is notoriously unstable and rate-limited.
* **To-Do:**
  - [ ] **Acquire Private RPC:** Get a dedicated Solana RPC URL from Alchemy, Helius, or QuickNode.
  - [ ] **WSS Support:** Enable WSS on the private RPC for real-time mempool scanning instead of HTTP polling.

### Ethereum (Etherscan)
* **Current Usage:** `https://api.etherscan.io/v2/api`
* **To-Do:**
  - [ ] **API Key Injection:** Ensure your `esKey` is actively being passed. The free tier is 5 calls/sec. Upgrade to Etherscan Pro if you hit limits, or shift token scanning to a dedicated node (Infura/Alchemy) via RPC.
